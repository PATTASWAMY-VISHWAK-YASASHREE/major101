- **REQ-004**: Report accuracy, balanced accuracy, F1, sensitivity/recall, specificity, confusion matrix, and the predicted-positive rate; do not use accuracy alone for model selection.
- **REQ-005**: Preserve case-level separation. No case may occur in more than one split, fold, or final evaluation set.
- **REQ-006**: Compute class-balanced loss counts from the training portion only; never use validation or test labels to derive training weights.
- **REQ-007**: Use `num_workers=0` on Windows unless a measured, repeatable test proves a safe alternative.
- **REQ-008**: Keep the feature-augmented model out of deployment claims because its ET-volume inputs reproduce the label-construction rule.
- **REQ-009**: Keep the test split generated by the verified seed-42 manifest locked until the final evaluation. The handoff records 88 test cases, but the manifest must be treated as authoritative because its other reported counts are inconsistent.
- **REQ-010**: Do not add CT loaders, CT preprocessing, CT/MRI fusion, or CT experiments to the BraTS MRI pipeline before every MRI completion-gate task in Phase 8 is complete.
- **CON-001**: Target no more than 2 GiB reserved VRAM and no more than 3 GiB process RAM on the RTX 2050 / Windows environment. Keep `num_workers=0`, batch size 2, AMP, and mmap loading unless a measured smoke test proves a safer alternative.
- **CON-002**: Use `str(path)` for `torch.save()` checkpoint paths on Windows.
- **CON-003**: Do not delete the approximately 95 GB preprocessed dataset until final checkpoints, split manifests, metrics, and reproducibility evidence have been verified and deletion has been explicitly approved.
- **CON-004**: The current checkout does not contain the handoff's referenced `src/losses.py`; loss implementations currently exist inline in `scripts/train_classifier.py`, `scripts/train_ultra_light.py`, and feature-model scripts. The plan must use the actual checkout locations and may consolidate them only as an explicit refactor.
- **GUD-001**: Prefer one canonical model/loss implementation over duplicated definitions in inference and visualization scripts.
- **GUD-002**: Run short smoke tests before any multi-hour training job and save each run's configuration beside its outputs.
- **GUD-003**: Mark ultra-light work experimental unless it meets the stability and performance gates in Phase 2.

### Bounded BA75 search implementation

The next improvement attempt is implemented as a bounded, resumable funnel,
not an unbounded background trainer. `scripts/background_search.py` creates a
fixed subject-disjoint search pool and a separate confirmation split from the
788 development cases, keeps the 88-case locked test outside every operation,
screens deterministic configurations with three-fold pooled OOF metrics, and
confirms a candidate only when both search OOF and independent confirmation
balanced accuracy reach **0.75**. It stops at the first of 100 attempts, 30
hours, or a passing confirmation. `scripts/start_background_search.ps1` runs
the same process hidden with stdout/stderr logs and `--resume` support.

## 7. Risks & Assumptions

- **RISK-001**: `grade_proxy` is an ET-presence proxy, so high validation/test accuracy may measure recovery of the labeling rule rather than independent glioma grading.
- **RISK-002**: The 88-case test set is small; five-fold estimates and confidence caveats are required before making performance claims.
- **RISK-003**: Batch size 2 and random 96³ crops can produce high variance; cross-validation is required before treating one split's score as representative.
- **RISK-004**: Duplicate model definitions in training, inference, and visualization can silently make checkpoints incompatible; canonicalization is required before final artifacts.
- **RISK-005**: Windows PyTorch/CUDA processes can fail with access-violation memory errors during ad-hoc repeated probes; keep `num_workers=0`, use one canonical evaluator, and check `nvidia-smi` before another run.
- **RISK-006**: Raw segmentation masks, paired CT scans, and longitudinal timepoints may not be present in the current workspace; downstream phases are conditional.
- **RISK-008**: CT/MRI datasets may have incompatible labels or unregistered acquisitions; no fusion result is valid until the paired-data contract and label provenance pass.
- **RISK-007**: Deleting preprocessed data is difficult and expensive to reverse; cleanup is gated by explicit approval.
- **ASSUMPTION-001**: `M1_best.pth` and its histories are readable and correspond to the architecture/configuration described in `HANDOVER.md`; verify this in TASK-001 before relying on it.
- **ASSUMPTION-002**: `data/brats_preprocessed/labels.csv` contains the `case` and `grade_proxy` columns described in the handoff.
